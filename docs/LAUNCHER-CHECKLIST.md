# 启动器开发与验收规范

本文档是 `启动图片批注查看器.bat` 的**修改与验收标准**。任何对启动器的修改，都必须遵循本规范的编写纪律，并通过第 4 节的完整验收流程，才算完成。

配套自动化脚本：`python scripts/verify-launcher.py`

---

## 1. 为什么需要这个规范（历史事故记录）

启动器是一个只有百余行的 bat，但曾在它身上集中爆发过四类问题，每一类都导致了误判和返工：

| 事故 | 根因 | 教训 |
| --- | --- | --- |
| 启动后浏览器不打开 | Vite 只绑定 IPv6 `[::1]`，探针连 `127.0.0.1` 永远失败；`.NET Framework` 的 `TcpClient` 创建 IPv6 连接还需显式指定地址族 | Windows 上 localhost ≠ 127.0.0.1；探活一律用 HTTP 请求（WebClient/curl），不用裸 TCP |
| 测试误报"启动失败" | 测试脚本用 DETACHED_PROCESS 拉起 bat，PowerShell 在分离控制台行为失真；验证用 urllib 连 IPv4 而服务在 IPv6 | 验证方式必须还原真实使用场景（双击 = 附加控制台）；验证工具用用户视角的工具（curl/浏览器） |
| bat 中文乱码、逻辑错乱 | bat 需要 GBK + CRLF，反复手工补丁导致 LF 行尾、`\v` 转义成 `\x0b`、`>nul` 被改成 `>/dev/null` | bat 是**构建产物**：只允许"生成脚本整体重写 + 字节自检"，禁止零散手工补丁 |
| 一开两个窗口（3000+3002） | 无单实例保护，多实例竞争端口文件；vite 端口被占时静默顺延到别的端口 | 单实例锁 + `--strictPort` |

---

## 2. 编写纪律（修改 bat 时必须遵守）

1. **编码**：文件必须是 **GBK（cp936）编码 + CRLF 行尾**。任何修改后都必须跑字节自检（脚本已内置）：
   - 无裸 LF（`\n` 数量 == `\r\n` 数量）
   - 无控制字符（`\x0b` 等，只允许 `\t \r \n`）
   - 全文可用 cp936 解码
   - 无 `/dev/null` 字样（防 `>nul` 被工具链误改写）
2. **整体重写优于局部补丁**：改动超过一两行时，用生成脚本整体重写 bat，不要在旧文件上叠多次零散编辑——每次补丁都是编码/行尾损坏的机会。
3. **heredoc 陷阱**：在 Git Bash heredoc 中生成 bat 内容时，反斜杠（`\v`、`\p` 等）会被吞、 `>nul` 可能被改写。生成后**必须**字节级核对关键行。

## 3. 实现原语（写什么、不写什么）

**推荐：**
- 端口探测：`IPGlobalProperties.GetActiveTcpListeners()` 查监听列表（同时覆盖 IPv4/IPv6，无绑定副作用）
- HTTP 探活：`System.Net.WebClient.DownloadString('http://localhost:PORT/')`（解析行为与浏览器/curl 一致）
- PowerShell 一律用全路径：`%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`（PATH 里可能没有）
- `npm run dev -- --port %PORT% --strictPort`：端口被占就报错，绝不静默换端口
- 单实例锁：`mkdir` 锁目录（原子操作）+ 锁内记录端口；有效性判定依次看"服务可访问 → 端口有监听 → 锁很新"，其余视为残留锁清理

**禁止：**
- `for` 代码块内嵌管道（`netstat | findstr`）——在部分环境下卡死或直接报错
- 裸 `TcpClient` 连 localhost/127.0.0.1 做探活（IPv4/IPv6 陷阱）
- 固定路径的共享临时文件（多实例竞争）；临时状态一律放锁目录内

## 4. 验收流程（每次修改后必须执行）

### 4.1 自动化验收（必过）

```bash
python scripts/verify-launcher.py
```

前置条件：3000-3009 端口全部空闲（脚本会自检并中止，防止误碰正在使用的实例）。

检查项（共 11 项，必须全过）：
- 字节自检 ×4（CRLF / 控制字符 / GBK / 无 dev/null 篡改）
- 场景 A 正常启动 ×4：页面可访问、锁创建、端口记录一致、停止后端口释放
- 场景 B 重复启动 ×2：提示"已在运行"且不启动第二个服务、实例数为 1
- 场景 C 残留锁 ×1：强制关闭后重启能识别并清理残留锁、正常启动

### 4.2 手工验收（自动化覆盖不了的）

1. **真实双击** `启动图片批注查看器.bat`，确认浏览器**自动打开**应用（自动化用 PV_NO_BROWSER 跳过了该分支）
2. 确认控制台中文显示正常、无乱码
3. 确认窗口标题为"图片批注查看器（关闭本窗口即停止）"
4. 关闭窗口，确认 3000-3009 无残留监听
